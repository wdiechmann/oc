# Unposted journal preparation

The current UI uses [work-in-progress paired rows](journal-work-api.md). The explicit review API below remains supported for legacy clients and audit workflows; an empty journal can now be created before any lines are entered.

All routes under `/api/v1/tenants/:tenant_id/finance/books/:book_id/journals` require a registered backend and current EP session. Current explicit book configuration stewards may prepare/revise unposted drafts; tenant administrators may inspect. This narrowly extends draft preparation, not approval, posting, payment, account balances or external accounting execution. No financial posting endpoint is introduced. Book hierarchy grants no authority. All amounts are exact whole minor units of the book's base currency; no FX conversion is inferred.

- `GET /?draft_id=uuid&version=integer`: projected draft index, optional current/historic snapshot, freshness, current preparation permission, current posting-account/VAT options and current configuration contexts. Histories retain dates, references, amounts, selected accounts, VAT/period validation evidence and actor/application/UTC acceptance time. Saved validations are marked stale when setup, periods or book version changes. A known newly accepted draft awaiting projection returns pending rather than 404; unknown scope/revisions remain 404. Pending/stopped/revoked views cannot provide mutation authority.
- `POST /reviews`: exactly `{draft_id: uuid|null, expected_draft_version: integer|null, expected_version: integer, contexts, data}`. `contexts` is the current exact `{setup_version, period_version, book_version, base_currency, accounting_authority}` returned by GET. `data` is `{name, posting_date, reference, lines}`; one date applies to every line. Names are nonblank trimmed Unicode ≤120 characters; references may be blank, also ≤120, without control/format characters. Dates are strict ISO calendar dates.
- Each line is exactly `{id: uuid|null, account_id: uuid|null, reference, debit_minor, credit_minor, vat_entry_id: uuid|null, net_minor: integer|null, assessed_vat_minor: integer|null}`. Stable line IDs survive revisions; missing IDs are generated in the private review. Debit/credit are nonnegative integers ≤9,000,000,000,000 each. Optional VAT amounts are signed within that bound. Blank account choices or zero/both-side entries can remain unfinished drafts, with explicit validation errors. Foreign/nonexistent account IDs and non-VAT catalogue IDs are rejected; same-book inactive/retired/non-posting accounts remain explicit draft issues. Without a VAT selection, VAT base/assessed fields must be null.
- `GET /reviews/:review_id`: identity/backend/book-scoped private one-hour review, using existing expiring ChartImport storage with purpose journal_draft. Returns normalized data, previous saved snapshot, exact validation evidence, configuration contexts, expiry, digest and expected journal-registry version. Review writes no journal fact, balance or financial result.
- `POST /accept`: exactly `{review_id, digest, expected_version}` plus Idempotency-Key. Current authority is checked before replay. Acceptance fences the book-local journal registry and original draft version, review purpose/scope/expiry, digest and configuration contexts. It recomputes validation under the same guards, then atomically records JournalDraftCreated/Revised, protected draft/registry state, outbox and FinanceJournalDraft:save receipt. A reviewed draft with issues may be explicitly saved; it remains unposted. Another key cannot accept the same review again. Original accepted retries resolve receipts even after expiry or view stop, subject to current authority. VERA retains only the small unchanged review pointer/key in its encrypted unknown-outcome session.

Validation checks each account's current book scope, posting type, active/retired state, exactly one nonzero debit/credit side, at least two lines/nonzero totals, exact debit/credit equality and the inclusive protected accounting period's open state. An account with a configured VAT choice but no selected journal VAT produces a visible review warning. 'prepared' means these local draft checks passed at review, not complete posting eligibility or financial authorization. Any errors/warnings produce needs_attention; both statuses are unposted drafts.

VAT is explicitly selected per line, with a separately entered signed net base. Resolve the active effective rule under the shared setup lock, using the journal date. Reuse VatRules.calculate's pure integer arithmetic, half-away rounding and deductible/reporting calculations. Import-statement assessment requires the explicit signed assessed VAT amount; supplier net does not infer customs assessment. Save the selected rule ID/version, rate/share, assessment basis, amounts, reporting values and date as review evidence. Missing/inactive rules, invalid bases and missing import assessments remain visible draft errors rather than rolling back otherwise valid unfinished drafts. The reporting summary is marked partial when VAT errors exist.

VAT quote amounts are separate from entered debit/credit amounts and generate no counter-lines. Draft preparation does not establish whether all required tax legs/accounts, dimensions or external-authority requirements have been fulfilled. A future posting handler must independently reauthorize, enforce activated-book/accounting-mode policy and open-period/account/VAT guards, generate/validate any explicit VAT posting legs, pin accepted versions/amounts, and atomically commit a complete balanced posting set. It cannot rely on an old draft's prepared flag.

Lock order: current principal/tenant and shared setup book guard, book row share lock, book journal guard, then period guard; protected period and VAT rows are shared while validating/accepting. Setup/account/VAT/steward changes and period transitions contend on the existing book guard; book metadata changes contend on its row lock. Context/version changes require explicit re-review. Accepted draft facts use a separate per-book finance_journals stream, protected JournalState/JournalDraft and asynchronous JournalView history, with finance_journals control, inbox/outbox, worker, pending-delivery recovery and deterministic side-effect-free query rebuild.

Limits: 100 drafts per book, 100 lines per draft. Histories preserve previous interpretations after correction or account/configuration changes. No autosave, ledger posting, approval, export, numbering policy or money movement. Responses are no-store and VERA filters financial form fields from logs. Private drafts/reviews use EP only, not a VERA business database.

Errors: 401 authentication, 404 current scope/authority/review/draft, 409 stale/pending configuration or journal, digest/idempotency/already-accepted conflicts, 410 expired review, 422 malformed dates/fields/amounts/references or limits, 503 stopped/unavailable views. Unknown acceptance requires private receipt check followed only by an explicit unchanged retry. The storage migration seeds no real drafts or transactions.
