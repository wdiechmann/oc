# Effective-dated VAT configuration

All routes are under `/api/v1/tenants/:tenant_id/finance/books/:book_id/vat-rules`, requiring a registered backend and current session. Existing book configuration stewardship governs writes; tenant administrators can inspect. Rules bind only to VAT catalogue UUIDs from the same book, never account-category entries. Rates are explicit configuration; no values are inferred from imported labels or statutory presets.

- `GET /`: projected rules, immutable revision histories, current VAT entry options, setup freshness and permissions.
- `POST /`: `{vat_entry_id, valid_from, valid_until, direction, rate_bps, deductible_bps, mappings, expected_version}`. A new rule is active and its ID equals the VatRuleCreated event ID.
- `PATCH /:rule_id`: the same fields plus `{active, expected_rule_version}`. Parent VAT entry is immutable. Setup and rule revisions fence edits. Rule revisions/deactivation/reactivation append facts; earlier accepted snapshots stay immutable.
- `GET /quote?vat_entry_id=...&date=YYYY-MM-DD&net_minor=...`: read-only exact arithmetic from protected accepted configuration. Returns selected rule ID/version, explicit rounding-policy tag, rates, direction, net/VAT/deductible/non-deductible minor amounts, invoice total and per-box signed sums. This does not accept a journal or grant financial authority. It can reflect accepted rules before the query projection catches up.

Date-only ranges are inclusive in the book calendar; a null end is ongoing. Active ranges for one VAT UUID cannot overlap, including a shared end/start day. Adjacent periods, inactive history and gaps are allowed; a gap fails with vat_rule_missing rather than silently assuming zero tax. The same setup advisory lock serializes rule/label/grant changes and protected date selection. New rules require an active VAT entry; inactive entries/rules cannot be selected for a quote. Existing rules remain attached through catalogue renaming, account import/replacement or reordering.

Percentages are integer basis points: 2500 is 25.00%; 10000 is 100%. Both rates and deductible shares must be 0–10000. Directions: input, output, reverse_charge, none. Output requires a zero deductible share; none requires both percentages zero. Input/reverse-charge shares apply to assessed VAT. A no-VAT rule may omit mappings; other directions require at least one. At most four mappings `{box, component, sign}`: box is trimmed Unicode text of 1–60 characters without control/format characters; component is net/vat/deductible_vat/non_deductible_vat; sign is +1/-1. Repeated box/component pairs are rejected; distinct components may sum into a shared box. Boxes are explicit book-local reporting identifiers, not predefined statutory interpretations.

The quote API accepts one integer net base in the caller's minor units, bounded to ±9,000,000,000,000. VAT is net × rate_bps / 10000, rounded to the nearest integer with ties away from zero. Deductible VAT is assessed VAT × deductible_bps / 10000 with the same rounding; non-deductible is the exact remainder. Credits retain the corresponding negative signs. Input/output invoice totals are net + VAT; reverse charge/none invoice totals are net. Reporting lines sum the signed selected components. This is a configured single-base calculation, not an invoice aggregation or tax filing engine.

Commands share the existing setup stream, current-authority-before-replay guard, idempotency keys and `FinanceSetup:vat_rule_create` / `FinanceSetup:vat_rule_revise` private receipts. Projection stops, source lag and rebuild remain explicit. Rule histories retain dates, percentages, mappings, lifecycle, actor/application and acceptance time. Before calculating a historic posting, use that posting's pinned accepted rule/version/amount snapshot, not a fresh resolution after a later rule correction.

Future authorized posting handlers may call `VatRules.lock_rule!` only inside their acceptance transaction, retaining the setup advisory lock and selected rule share lock through commit. Acquire the canonical book/setup guard before period/account row guards, and separately enforce book activation/accounting authority, financial authorization and the open-period guard. Persist the selected rule/version and values in the financial fact; this slice activates no posting or payment execution.

Errors: 401 authentication, 404 scope/authority/rule, 409 revision/idempotency/overlap/uninitialized conflicts, 422 invalid fields/reference/amount or missing effective rule, 503 stopped setup view. Responses are no-store. The migration creates rule storage only; no real rule/rate is seeded.
