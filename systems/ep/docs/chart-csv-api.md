# Reviewed CoA CSV transfer (v1)

All routes are book-scoped under `/api/v1/tenants/:tenant_id/finance/books/:book_id`. Require a registered backend and current operator session. Tenant administrators may export/read setup metadata; uploads, previews and acceptance require explicit active book stewardship. Import reviews are private to the creating identity/backend, expire after one hour and are deleted by a scheduled cleanup worker. VERA parses/encodes CSV; EP validates every domain field and owns the review/atomic acceptance.

- `GET /chart-imports`: transfer information, current projected setup status, permissions, canonical columns and upload limits.
- `GET /chart-export`: one ready projected snapshot, with optional `q` number/name filter and optional matching `source_version`. Returns columns/string rows, scope, source revision and row count. No paginated accumulation/mixed snapshots. Pending/stopped/stale queries are refused.
- `POST /chart-imports`: `{headers, records, create_codes?, mode?}` stores a bounded private draft upload, not an accepted financial change. UTF-8 CSV is parsed by VERA into string arrays. Max 500 records, 32 columns and 2 MiB. Exact duplicate/blank headers and inconsistent row widths are rejected. No source filename is retained.
- `GET /chart-imports/:import_id`: private upload/column mapping/review, proposed creates/revisions/unchanged rows and errors.
- `POST /chart-imports/:import_id/preview`: `{mapping, create_codes?, mode?}` maps logical fields to uploaded header names. Name/position are required mappings; optional unmapped fields preserve existing values or use new-row defaults. Blank mapped fields explicitly clear optional values. Canonical scope/version columns are always checked when present. Preview validates protected current state without writing accounts/events. Re-preview replaces the digest; an old review cannot be accepted.
- `POST /chart-imports/:import_id/accept`: `{digest, expected_version}` with Idempotency-Key accepts exactly the reviewed valid plan, after current authority/expiry/owner/setup/account/reference checks. A changed chart/catalogue invalidates the review. Original receipts use `FinanceChartImport:accept` and the existing private `/me/commands` query. Receipt checks never replay mutations; identical explicit retries stay idempotent, even after draft cleanup. Another key cannot reapply an accepted review.

Canonical columns: schema_version, tenant_id, book_id, source_version, account_id, account_version, type, number, name, vat_entry_id, vat_code, category_entry_id, category_code, position, formula, active. Version is `1`. CSV preserves account numbers as strings; positions/versions use strict integers and active uses true/false. Match by stable account_id when supplied (unknown/foreign IDs are errors), otherwise by posting number in this book, otherwise create. Blank IDs for header/calculation rows create new rows. In merge mode, missing source rows stay unchanged. In replace mode, omitted current accounts are retired and made inactive, with their identities and history retained. Optional supplied account versions and source revisions must be current.

Catalogue UUIDs are primary; code-only inputs resolve current entries. Supplying both must describe the same current code/entry, preventing unnoticed reassignment. Retained inactive associations may remain; new inactive/foreign/wrong-kind references fail. Validate the whole final chart, including rows not in the file in merge mode, or only the successor rows in replace mode: number reservations, duplicate IDs/numbers/positions, type-specific fields, formula syntax/stable references/forward references and cycles. Account numbers remain reserved after renumbering. Position swaps are accepted together under a deferred unique constraint; no partial reorder is committed. New account IDs equal their AccountCreated event IDs. Changed rows emit individual account events under one command; unchanged rows keep their revisions. Projection delivery finishes a command group atomically even at a worker page boundary. Rebuild executes no financial work.

CSV uses UTF-8 (optional BOM), detected comma/semicolon/tab delimiters, empty-row skipping, quoted fields and embedded quoted newlines. No numeric converters touch identifiers. Exports use a reversible apostrophe escape for text beginning with an apostrophe or spreadsheet formula trigger (`= + - @` after whitespace); import removes one defined escape. CoA formulas remain text and are never evaluated by CSV handling. CSV cannot encode spreadsheet cell types: import identifiers as Text in spreadsheet apps to preserve leading zeroes. Downloadable templates include one demo header row with the current tenant_id/book_id, name `demo`, position `100` and active `true`. Replace or remove it before importing real rows.

Errors: 401 authentication; 404 scope/review/access; 409 version_conflict, view_pending, chart_changed, digest_conflict, invalid_review, import_already_accepted, idempotency_conflict; 410 review_expired; 422 invalid_upload/invalid_mapping; 503 view_stopped. Review row errors are returned as data and disable acceptance. Views distinguish accepted facts from projection readiness. This slice imports chart configuration only, not balances, journals, catalogue definitions or periods.

The optional boolean `create_codes` defaults to false. It is retained from upload for the mapping form; preview explicitly chooses the current option and binds it to the digest. When enabled, preview proposes one entry per distinct missing mapped VAT/category code (case-insensitive), names it after the code, and shows it before acceptance. Existing codes are reused; invalid/reserved codes and inactive/new associations still fail validation. No catalogue writes occur during preview. Acceptance creates the reviewed entries and account changes in one transaction/command, with individual CatalogueEntryCreated facts followed by account facts; replay/rebuild retain their histories. Account types remain header/calculation/posting.

Blank or unmapped account types are guessed and marked in review: a number implies posting; a formula, or an unnumbered row immediately following postings, implies calculation; other unnumbered rows start as headers. Explicit types always win. These guesses do not bypass validation: calculations still require valid formula text and posting rows require valid account numbers. The template demonstrates header; the form lists posting and calculation as the other supported types.

VAT and account-category values belong to independent catalogues, including when their text is identical. Both accept descriptive Unicode text up to 120 characters, such as `Dansk salgsmoms`, `UEUV - Varesalg EU - indberettes (rubrik B - varer)` and `Indtægt`; import preserves the full value instead of guessing a code/name split. Deduplication, reservations and UUID assignments remain scoped by book and catalogue kind.

## Replacement and retirement

New uploads default to `mode: replace`; merge is an explicit alternative. Legacy uploads/reviews created before mode support retain merge semantics until an explicit re-preview selects replacement. The mode, retained count and complete list of retirements are shown in the review and covered by its digest. Changing modes requires a new preview/digest. Acceptance uses only the stored reviewed mode, never a replacement body parameter.

Replacement validates positions/formulas against the complete successor chart, retaining accounts matched by stable ID or posting number. Current rows omitted from the file are retired in the same atomic command. Retirement is separate from ordinary inactivity: retired accounts are inactive, absent from the current chart/export and unavailable to line-editor changes; inactive current accounts remain in the chart and retain positions. Retired rows keep their numbers, positions, formulas, references and catalogue versions. Numbers remain reserved for the original identities. An import matching a retired ID/current number explicitly restores that identity rather than assigning its number to a different account. A restored row defaults to active when active is unmapped. Former reserved numbers cannot be reassigned to other IDs.

`AccountRetired`/`AccountRestored` patches replay through the existing setup outbox/inbox. The protected table's generated position scope keeps current-chart uniqueness deferrable while allowing retired historical positions to coexist. The setup projection retains retired rows; `GET /setup/accounts?retired=1` serves paginated, read-only history (configure=false); normal setup/chart/export excludes those rows. Current formulas must resolve entirely within the successor chart. No account/event is deleted and no journal/ledger migration is performed. Empty CSV uploads remain invalid. The migration changes constraints/metadata only; no existing account is retired automatically.

The optional `vat_basis` column round-trips posting account inclusion defaults (`gross`, `net`, blank for unspecified). Unmapped fields preserve the existing account value in merge mode; replacement accounts without a mapped default remain unspecified. Imported labels never infer inclusion.
