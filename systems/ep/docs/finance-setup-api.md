# Finance setup contract

All routes require a backend credential and a current operator session. Base:
`/api/v1/tenants/:tenant_id/finance/books/:book_id/setup`.

- `GET /`: current permissions, projected accounts/bindings, source/latest setup versions and ready/pending status. Tenant administrators may inspect setup and assign/revoke stewards; only an explicitly assigned steward may change accounts or bindings. No inheritance from parent books or occasion administration. No posting/payment authority is granted.
- `POST /stewards`: `{identity_id, active, expected_version}`. Tenant administrators explicitly assign/revoke the role. Initial UI candidates are existing active tenant/occasion administrators; the API accepts an existing active verified identity UUID. No identity is created.
- `POST /reopening-authority`: `{identity_id, allow, expected_version}` explicitly grants/revokes reopening permission for an already-active book steward; tenant administrators only. Steward revocation clears it. See [periods-api.md](periods-api.md).
- `POST /bindings`: `{occasion_id, active, expected_version}`. A steward binds/unbinds a current draft/active occasion in this tenant. Each occasion has at most one book; several occasions may share a book. An existing binding must be removed by that book's steward before reassignment. Unbinding does not rewrite occasion-owned records.
- `GET /accounts`: a canonical-position chart page. Query `page` (default 1), `per_page` (default 50, max 100), optional `q` (number/name filter), `focus_id` (locate a saved row), and optional `source_version`. Returns `accounts`, `pagination` (`page`, `per_page`, `total_entries`, `total_pages`), permissions, dropdown options, and accepted/source setup revisions. Supplying `source_version` requires that exact ready projection; otherwise `chart_changed` (409) stops infinite append. No mixed-revision pages are returned.
- `POST /accounts`: `{kind, name, position, expected_version, ...type_fields}`. Types: `header` has name/position; `calculation` adds formula; `posting` adds number/VAT/category. Irrelevant type fields are cleared synchronously. Posting numbers remain strings, unique/reserved within the book, including leading zeroes. VAT/category selections use book-local stable `vat_entry_id`/`category_entry_id` references from [the catalogue API](catalogues-api.md). Until initialization, legacy code requests remain compatible. These are classifications, not activated tax rates or calculations.
- `PATCH /accounts/:account_id`: the same row fields plus `active`, `expected_account_version`, `expected_version`. Account ID remains the initial AccountCreated event ID. Positions are unique positive integers within a book and order independently from numbers. A move requires current setup and account versions. Old numbers stay reserved after a type change or renumbering.

Formula text supports decimal constants, parentheses, unary signs and `+ - * /`, with `[account-number]` or `[@account-uuid]` references. EP pins references to stable IDs, checks book scope and rejects headers, unknown references and cycles. An unchanged formula retains its original bindings after account renumbering. Formulas are validated/stored here; ledger-result evaluation follows with reporting. A reference to another unnumbered calculation uses its stable UUID (`Copy ref` in VERA).

Legacy `heading`/`total` kinds remain accepted aliases for `header`/`calculation`. Older clients may omit positions (append with a gap of 100; revisions keep their position). Legacy projected rows are normalized deterministically; former total labels have no invented calculation value and require a formula when next edited.

Mutations require `Idempotency-Key` (1–128 safe characters), reject extra fields, and return command/book/tenant/event IDs, stream_version and replayed. Use `/api/v1/me/commands?command_type=FinanceSetup:<action>&idempotency_key=...` for private original-receipt reconciliation; actions are `steward`, `reopening_authority`, `binding`, `account_create`, `account_revise`. Authority is checked before replay. Errors: 401 unauthenticated; 404 unavailable scope/access; 409 version_conflict, number_taken, position_taken, binding_taken, chart_changed, idempotency_conflict; 422 invalid_setup/invalid_formula; 503 view_stopped. A lost response never establishes rollback.

Protected current tables and per-book transaction locks govern acceptance and revocation. A tenant/occasion lock protects competing bindings. `finance_setup` events publish snapshots through outbox/inbox to a background MV; reads expose lag and refuse stopped controls. Grant candidates/current authority are live restricted control data, not financial authorization from the MV. The view can be rebuilt without appending events or dispatching financial work. Position order and formula configuration are supported; batch reorder/rebalancing, imports, periods and journal permissions follow later slices.

Example account command: `{"number":"0010","name":"Bank","kind":"posting","position":100,"vat_code":"none","category":"assets","expected_version":1}`.

Reviewed chart CSV import/export is specified in [chart-csv-api.md](chart-csv-api.md) and [chart-csv-openapi.json](chart-csv-openapi.json). Single-line commands and historical setup snapshot replay remain compatible.
