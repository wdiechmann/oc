# Native chart ordering (v1)

Book-scoped routes under `/api/v1/tenants/:tenant_id/finance/books/:book_id` require a registered backend, a current session and explicit active configuration stewardship. Reordering uses a ready setup snapshot, initialized catalogues, the protected per-book setup lock, expected revisions, private reviewed digests and original-key receipts. No journals, membership or other accounting configuration change.

- `GET /chart-order`: complete current chart in accepted position order, including inactive rows and excluding retired history. Returns source_version, rows (`id`, number, name, kind, position, active), book metadata and max_rows (2,000). This is a complete snapshot, independent of chart search/page filters. Pending/stopped views fail closed.
- `POST /chart-order/reviews`: `{expected_version, ordered_ids}` must contain every current account UUID exactly once. Missing, duplicate, foreign, retired or additional IDs fail validation. Preview assigns positions 100, 200, 300… in the proposed order and returns a private review with before/after positions, per-account revision fences and changed counts. It writes only the expiring review, not accounts or events.
- `GET /chart-order/reviews/:review_id`: owner/backend-private review, expected_version, digest, expiry, plan and accepted status. Reviews expire after one hour; the existing cleanup worker removes expired review rows.
- `POST /chart-order/reviews/:review_id/accept`: `{digest, expected_version}` plus Idempotency-Key accepts exactly the reviewed order. Recheck current authority before receipt replay, then review ownership/purpose/expiry, readiness, setup revision, complete membership and the rebuilt plan. A changed chart requires a fresh review. Acceptance cannot substitute a new order.

Only changed positions, account stream revisions and actor/application attribution are updated. Names, numbers, kinds, active/retired flags, number reservations, catalogue IDs/accepted versions/codes, formula text and pinned formula references remain unchanged. Native ordering is a position-only operation, so it does not recapture current catalogue labels like an ordinary account edit. Deferred current-chart position uniqueness permits swaps; all changed rows, AccountRevised patches, outbox and one command receipt commit atomically. The existing projector finishes the complete command group and rebuilds without executing financial work. Unchanged rows emit no events; a no-op review may have a receipt with zero events.

Receipts use `FinanceChartOrder:accept` through the existing private `/me/commands` query. Original retries survive review cleanup; another key cannot reapply an accepted review. VERA stores only the small signed review ID/digest/version pointer and original key for unknown-outcome recovery. New mutations remain blocked until completion is checked; explicit retries reuse the original pointer/key. The shared private review table discriminates `purpose: chart_order`; CSV endpoints reject native reviews and native endpoints reject CSV reviews.

Errors: 401 session/backend; 404 scope/authority/review-purpose/owner/backend; 409 stale/version/digest/idempotency conflicts, already accepted, uninitialized catalogues or pending view; 410 expired review; 422 invalid order/oversized chart; 503 stopped view. Responses are no-store. No migration is required for native ordering.
