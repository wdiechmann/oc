# Book VAT/category catalogues

Base: `/api/v1/tenants/:tenant_id/finance/books/:book_id/setup/catalogues`.
Require registered backend/current session. Tenant administrators may inspect; only explicit active book configuration stewards initialize/create/revise catalogues. Parent/occasion roles confer no inherited finance configuration rights.

- `GET /`: projected entries/history, initialized flag, current permissions and setup source/latest revisions. Stopped setup projections return 503. Chart GET uses these same projected entries/labels, never a separate fixed dropdown list.
- `POST /initialize`: `{expected_version}` adopts the former three VAT and five category choices as editable book-local entries. Existing string selections are bound to stable entry IDs in the same accepted batch, without changing their codes/meaning or rewriting old events. This is an explicit steward operation, once per book; reads never seed data. New books use this same initialization workflow. No monetary rates/rules are created.
- `POST /`: `{kind, code, name, expected_version}` creates an entry (`vat` or `category`). UUID identity is independent from mutable code/name. Codes are 1–120 trimmed Unicode characters, including spaces and descriptive punctuation; control/format characters are rejected; names 1–120 trimmed characters. Codes are unique case-insensitively within book/kind and remain reserved after renaming/deactivation.
- `PATCH /:entry_id`: `{code, name, active, expected_version, expected_entry_version}` renames/revises/deactivates/reactivates an entry. Kind is immutable. Existing account associations remain intact. No deletion/reuse of reserved codes.

Commands require `Idempotency-Key`. Receipts use `FinanceSetup:catalogue_initialize`, `FinanceSetup:catalogue_create`, `FinanceSetup:catalogue_revise` through the existing private GET `/me/commands` lookup. Current authority precedes replay. Accepted results include book/tenant/command/event IDs, entry_id for entry create/revise, and setup stream_version. Extra fields, bad versions, scope/kind mismatches, duplicate codes and new assignments to inactive entries are rejected atomically.

Chart account commands now accept nullable `vat_entry_id`/`category_entry_id`, with current setup/account revisions. EP validates the referenced book/kind and active state from protected current rows. An unchanged inactive association may be retained or cleared; another account cannot acquire it. Accepted account snapshots retain selected entry IDs/versions and acceptance-time code strings; current labels are joined from the catalogue projection. Catalogue renaming/deactivation does not rewrite accounts or historical accepted snapshots. An explicit subsequent account save captures the then-current entry version/code for that new account revision. Header/calculation rows clear both associations.

Until explicit initialization, old API clients may continue their former validated string selections; the new chart UI offers no fixed choices and keeps chart editing disabled with an initialization link. Initialization binds all current legacy selections. After initialization, compatibility string requests resolve current codes, or retain their own former selection; they cannot assign a retired alias to a different account. New VERA forms send stable IDs.

All catalogue/account commands share the book setup authority lock and stream revision, preventing stale/racing assignments. Catalogue facts, projection/history, serving controls, outbox recovery and replay use the existing finance_setup pipeline. History includes actor/application/UTC/event/version and prior code/name/status. Rebuild creates only query data, never new accepted facts. Bootstrap entries have individual UUIDs within one batch event; ordinary creates use their event UUID. VAT entries are classification labels in this slice, without tax rates/calculation/posting rules.

Errors: 401 unauthenticated; 404 unavailable scope/authority; 409 version_conflict, code_taken, catalogues_initialized, catalogue_not_initialized, idempotency_conflict; 422 invalid_catalogue/invalid_catalogue_reference/inactive_catalogue_entry; 503 view_stopped. Responses are no-store. Dates, rates, tax obligations and posting semantics are outside this label-catalogue contract.
