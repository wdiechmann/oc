# Tenant book setup API — first slice

[OpenAPI](books-openapi.json). All endpoints require the current EP user Bearer; responses are no-store. The first-slice bootstrap policy permits **active tenant administrators to manage tenant-wide book metadata only**. Occasion-only administrators and platform monitoring operators do not acquire access by those roles. No finance posting, payment, document or consolidation-result authority is granted or implied. Future financial roles/permissions remain separate gates in system_2_plan.md.

| Method/path | Behavior |
|---|---|
| `GET /api/v1/tenants/:tenant_id/finance/books` | Tenant metadata list from the book MV, tenant name, source/latest versions and `status: ready|pending`. An empty new tenant is ready; an unprojected create is pending, not evidence that no book was accepted. |
| `POST .../books` | Create a draft book; requires Idempotency-Key. Returns command/event IDs, book ID, accepted tenant-stream version and replay flag. |
| `GET .../books/:id` | Current query-view book plus expected authoritative version; `book: null` until first projection. Pending is an explicit JSON status in a 200 response. |
| `PATCH .../books/:id` | Change name and/or parent_book_id using expected_version and Idempotency-Key. Returns the accepted reference/version; identical retries return the prior receipt. |

Creation fields: `name` (trimmed, 1–120 characters), `code` (normalized uppercase, 2–40 ASCII letters/digits/underscore/hyphen, starting with a letter/digit), `base_currency` (initial supported set DKK/EUR/SEK/NOK/GBP/USD), `accounting_authority` (`ep|external`), `timezone` (`Europe/Copenhagen|Etc/UTC`), `fiscal_year_start_month` (integer 1–12), optional nullable `parent_book_id`. The status starts as `draft`. Code is tenant-unique and, with currency/authority/calendar, immutable in this first slice; later changes require the appropriate configuration/migration workflow. No actual period, ledger, provider adapter or opening balance is created.

Books nest by parent ID in the **same table**, within one tenant. A composite foreign key prevents dangling/foreign-tenant parents. Tenant-local setup serialization and current ancestor checks reject self-parenting and cycles, including simultaneous opposite moves. Book metadata setup serialization does not serialize future journals/payments behind one global finance stream. Missing/foreign/inaccessible resources return the same 404.

Book setup events (`BookCreated`, `BookRevised`) use tenant scope, stream type `finance_books`, stream ID equal to tenant ID. Details contain a full basic book snapshot with stable book ID. These are tenant-wide setup facts; occasion-to-book bindings are not implemented yet. Current protected book state, facts, receipt, outbox and job enqueue commit atomically. A book's revision is its last setup event version; it can skip numbers because other books share the tenant setup stream. The global setup order gives hierarchy projections a consistent replay order.

Normal reads use `finance_book_view`; financial acceptance cannot use a lagging view. `mv_control` name `finance_books` gates serving/processing; stopped (or unexpectedly missing for existing books) returns 503. The protected command handler can accept authorized setup work while publication is stopped; VERA does not present stopped views as editable/current. Worker batches are bounded at 1,000, ordered/contiguous, idempotent through inbox records and acknowledged atomically. Existing pending outbox recovery now also wakes book workers. No raw event-ingestion or public rebuild endpoint is exposed.

Trusted operator-only `Ep.Finance.BookProjector.rebuild(tenant_id)` reconstructs this metadata view from complete supported history without appending facts, queueing or executing external actions. It does not rebuild all protected finance state and is not a complete finance privacy/erasure/backup implementation. Missing/unsupported/redacted history must fail, not silently recreate financial data. Finance-domain rights/holds and production restore acceptance remain required before wider use.

Errors: 401 unauthenticated; 404 inaccessible context; 409 code_taken/version_conflict/idempotency_conflict/hierarchy_cycle; 422 invalid_book/invalid_parent/invalid_key; 503 view_stopped. A timeout is unknown, not proof of failure. Use the existing private `GET /api/v1/me/commands?command_type=FinanceBookCreate|FinanceBookRevise&idempotency_key=KEY` to reconcile the original request; current authority is rechecked and no mutation is replayed. Actor/application trace and correlation follow the core EP boundary.

The initial metadata list is tenant-wide and intended for small book registries; pagination/search is a future scale extension. MVs update in the background; this API exposes no live subscription transport. VERA provides explicit refresh/pending status and inline mutation failures. Actual consolidation, occasion binding, chart of accounts, periods, posting, settlement and full finance grants are subsequent slices, not implicit effects of creating a book.

## Book detail and workspace navigation (2026-11-09)

Current explicit book stewards may read `GET .../books/:id` for their own book. The response includes `permissions.revise`, true only for a current tenant administrator. Tenant-wide listing, creation and metadata revision remain tenant-admin only. Occasion-only administration still grants no book access. Book details continue to require a running book view, expose pending projections explicitly and recheck current authority on every request.

`/me/workspaces` enriches accessible occasion cards with `book_id` and `book_name` using current tenant-local occasion bindings and running directory/book/setup projections. It also includes bound occasions visible through the user's tenant administration or explicit book stewardship. Occasion-only administrators retain their occasion cards without a book link unless independently authorized. Unbinding/revocation removes navigation access without relying on stale card claims; book endpoints enforce authority independently.


## Posted financial overview

Authorized book detail GETs now include `overview`. A ready result contains `status`, `currency`, fiscal `start_date`, timezone-local `as_of`, `prior_as_of`, twelve `months` (`month`, `income_minor`, `expenses_minor`, `future`), `totals` and `previous` (`income_minor`, `expenses_minor`, `profit_minor`), `change_bps` (same keys, nullable), `journal_count` and `classification_warnings`.

The existing book/setup authority lock covers the read. Setup projection control/readiness is checked separately; `overview.status` may be `pending`, `unavailable` or `external` while book metadata remains available. The single posted-fact query is tenant/book scoped and excludes drafts. Current income/expense category mappings include retained retired posting accounts and apply equally to both comparison periods. Income is credit-positive, expenses debit-positive, profit is their difference. The inclusive cutoff uses PostgreSQL’s book timezone; the prior cutoff is the same calendar date one year earlier, clipped for leap day. Comparisons use fiscal YTD only; basis points are null for nonpositive prior values. Future months have zero actuals and future=true, not forecasts. Reads do not append events or create another ledger. Facts are read on demand in this first version; a dedicated aggregate projection remains future scaling work.
